### 2.2 既存スクレイパー流用 adapter（`discovery_adapters/scraper_adapter.py`）
- `ScraperBackedAdapter`：`get_scraper(site, limit).scrape()` を実行し `ProjectCreate → DiscoveryCandidate` へ変換。`network_backed=True`。
- サブクラス：`WadizAdapter`（KR）/ `ZeczecAdapter`（TW）/ `UluleAdapter` / `IndiegogoScraperAdapter`。
- 変換方針：**欠損は推測せず null**。通貨・raw_data（amount/rate(逆算%)/participants|backers/categoryName/makerName）を保持。status はメモ（`[Wadiz]…Status:`）から `normalize_status` で正規化。**Zeczec enrichment があれば** maker_name/category/description/official_site_candidates を非破壊反映、無ければ null（エラーにしない）。description は enrichment を優先（一覧メモは状態要約のため）。
- scrape() の分類付き例外は握りつぶさず伝播＝**0 件を success にしない**。

### 2.3 レジストリ（`discovery_adapters/__init__.py`）を単一の真実源に
- `platform_availability()` / `is_live_fetch()` / `query_supported()` / `needs_fetch_injection()`。available は「fetch 注入（KS）or adapter.network_backed」。
- Kickstarter のみ検索クエリ対応、Wadiz/Zeczec/Ulule/Indiegogo は一覧取得型（query 非対応）。

### 2.4 非同期ジョブ（`discovery_job_service.py`）
- `POST /discovery/run`→`create_job` で即 `{job_id, platform, status:queued}`。デーモンスレッド実行。
- **CI とは別セマフォ**（`discovery_max_concurrent_jobs`、既定1）。
- 同一 platform×query×limit の queued/running を**重複作成しない**（`find_active`）。
- ジョブごと短命 `SessionLocal`。status='running' commit 後に adapter.discover（外部HTTP）→ 以降で保存。**外部HTTP中にトランザクション非保持**。
- 起動時に孤児（queued/running）を failed 回収（`main.py` lifespan に登録）。

### 2.5 API（`routers/discovery.py`）
- `GET /discovery/platforms`（対応状況・読み取り専用）。
- `POST /discovery/run`（ジョブ作成・準備中は400）。
- `GET /discovery/jobs/{id}`（進捗・結果・読み取り専用）。

### 2.6 スコアリング（`discovery_scoring_service.py`）
- 「大型調達」判定を **概算 USD 換算**に変更（KRW/TWD をそのまま USD と誤認しない）。`_APPROX_USD_PER_UNIT` で換算、しきい値 100k USD。
- achievement_rate は raised/goal 比率（通貨非依存）を維持。category/description 欠損は confidence 低下のみで **0 点にしない**。

## 2. 実装（backend）

### 2.1 モデル / migration（追加のみ・非破壊）
- `DiscoveryPromotionStatus`（not_promoted / promotion_pending / promoted / promotion_failed / duplicate_project）。

### 2.2 昇格サービス（`services/discovery_promotion_service.py`・新規）
- **重複判定** `find_duplicate_project`（優先順）：①`source_url` 完全一致（projects 全体）②`platform`+`source_id`（URL から slug / Wadiz campaign id を機械抽出、同一 source_site 内）③正規化URL一致（scheme/www/query/末尾 `/` 無視）。**近似一致（title+maker_name）は `find_approximate_matches` で警告のみ・自動統合しない**。

- **promote**：
  1. 既 promoted で project 生存 → 冪等に既存 id 返却（再作成しない）。
  2. 重複 project 検出 → `duplicate_project`・既存 id を返す（**新規作成しない**）。
  3. それ以外 → `promotion_pending` 記録 → `project_service.create_project` で非破壊作成 → `enrichment.provenance` に source_discovered_product_id / raw_data / 発掘スコア / brand_name / achievement_rate を保管 → `run_assessment`（同期・軽量）→ `create_job(full_contact_intelligence)` を queued（**重い探索は背景・同期POSTしない**）→ `promoted` 更新。
  - **推測しない**：maker_name=creator_name のみ、maker_url=official_website_url のみ、欠損は null。
- **promote_batch**：ID 重複除去・最大50件・1件ずつ独立・一部失敗継続・成功/重複/失敗/既昇格/不存在を個別集計。
- テスト用に `contact_runner` / `assessment_runner` を注入可（スレッド/評価を差し替え）。
