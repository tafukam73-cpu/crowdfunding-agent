## 🚀 次回スムーズに始めるための項目

### 環境・起動
```bash
cd C:/Users/pc/dev/crowdfunding-agent
docker compose up -d              # 3コンテナ起動（db / backend / frontend）
docker compose ps                # 稼働確認
```
- フロント: http://localhost:3000 ／ バックエンド: http://localhost:8000 ／ Swagger: http://localhost:8000/docs
- ヘルス: `curl http://localhost:8000/health` → `{"status":"ok","database":"ok"}`
- 主な画面: `/`（トップ営業ダッシュボード）, `/discovery`, `/discovery-dashboard`, `/crm`, `/crm/makers/{id}`（メーカー詳細＝SalesMakerPanel＋CompanyIntelligence＋営業活動タイムライン）, `/sales-opportunities`

### 品質チェックの回し方（このプロジェクト固有）
```bash
docker compose exec -T frontend sh -lc 'cd /app && npx tsc --noEmit'   # 型チェック（これで担保）
```
- ⚠️ **`npm run lint` は使えない**（ESLint 未設定で対話プロンプトになり停止）。型検証は `tsc` と `next build` で担保する。
- ⚠️ **dev コンテナ内で `npm run build` を実行しない**こと。稼働中 `next dev` と同じ `.next` に本番出力が混ざり破損する。もし実行してしまったら `docker compose restart frontend`（起動時に `.next` 自動クリア）で復旧する。

### バックアップ / 復元
```bash
./scripts/backup-db.sh                 # backups/ に日時付き + latest.sql
./scripts/restore-db.sh                # latest.sql から復元（復元前に現DBを自動退避）
./scripts/restore-db.sh backups/xxx.sql --yes
```

### 🚫 絶対にやらないこと（DB喪失防止）
- `docker compose down -v` 禁止（db_data ごと消える）
- `docker volume prune` 禁止（旧ボリュームを巻き込む）
- `db_data` ボリュームの手動削除禁止
- 破壊的操作の前は必ず `./scripts/backup-db.sh`

### よくあるハマり
- **ダッシュボードが「読み込み中/取得できません」で固まる** → だいたい**古いブラウザタブ**が原因（フロント再起動で `.next` の `?v=` が変わり旧チャンクが404）。**ハードリフレッシュ（Ctrl+Shift+R）**で解消。バックエンド/DBは別途 `health` とAPIの200で確認する。
