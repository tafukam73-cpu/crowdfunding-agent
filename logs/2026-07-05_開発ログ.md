### 背景 / 原因
- 「〜に下書き作成」ボタンは `createProviderDraft`（バックエンドAPI）を呼ぶだけで、**Gmail 画面に遷移しなかった**。
- メールプロバイダーが `mock`（AI未接続）の状態では下書きはサーバーにも Gmail にも作られず、画面内に「モック下書きを作成しました」と表示されるのみ。`web_link`（Gmailで開くリンク）が返るのは実 Gmail 連携時だけで、通常は開くものが何も無かった。

### 対応内容
- **API 連携ではなく Gmail の compose URL を直接開く方式**に変更。
  - URL 形式: `https://mail.google.com/mail/?view=cm&fs=1&to=...&su=...&body=...`（`view=cm&fs=1` = 作成画面。送信ではない）
  - `to` / `su`(件名) / `body` は `encodeURIComponent`。
  - `window.open(url, "_blank", "noopener,noreferrer")` で新規タブ起動。
- **状態別 UI**:
  - 宛先メール未登録 → 「メールアドレスが未登録です」表示。
  - ポップアップブロック時 → Gmail リンクを画面表示して手動クリック可能に。
  - 正常オープン → 「作成画面を開きました（送信されていません）」表示。
- 既存 UI デザイン（indigo 系ボタン・角丸・xs 文字）に合わせた。

### 変更ファイル
- `frontend/lib/api.ts` … `buildGmailComposeUrl()` / `openGmailCompose()` を新規追加（+30）。
- `frontend/components/EmailDraftPanel.tsx` … ボタンを「Gmailで下書きを開く」に変更、API 呼び出しを compose URL 起動に置換、フィードバック UI 追加、不要になった provider(mock/gmail) 関連の状態・表示を整理（149 行変更）。
- `frontend/components/SalesMakerPanel.tsx` … 営業メール生成後に「Gmailで下書きを開く」ボタンとフィードバック UI を追加。宛先は「メールアドレス」欄の値を使用（+77）。

## 2. 連絡先メール発見の精度改善（`49914b9`）

### 背景 / 原因
- Kickstarter 由来などで `example@example.com` / `maker@example.com` 等のダミーや no-reply、404ページ由来のメールが「連絡先」として表示されていた。
- ダミー除外は `example.com` 完全一致のみで、`test.org`/`dummy`/`sample`/ローカル部ダミーを弾けず。Playwright フェッチャーは **HTTPステータスを無視して本文を返す**ため 404 ページからメール抽出が起きうる状態。

### 対応内容
- 共通バリデーション `email_validation.py` を新設：`is_valid_business_email()` / `business_email_reason()`。ブラックリスト（example/test/dummy/sample のドメイン・ローカル部、no-reply系、形式不正）。
- `email_exclusion_reason` に統合し、抽出・AI再検証・営業ランキングの全経路で一元除外。
- `web_research_service` / `recursive_crawl_service` に **非200（404/410/5xx）本文の破棄ゲート**を追加。
- 連絡先に信頼度（高信頼/要確認/未検証）を付与、メール0件時は `fallback_search_queries`（公式サイト/Google/LinkedIn/site: 検索導線）を返し UI 表示。CRM登録時も無効メールを弾く。

### 変更ファイル
- backend: `services/email_validation.py`（新規）, `contact_discovery_service.py`, `contact_hunter_service.py`, `web_research_service.py`, `recursive_crawl_service.py`, `models/contact_discovery.py`, `schemas/contact_discovery.py`, `tests/test_email_extraction.py`
- frontend: `components/ContactDiscoveryPanel.tsx`, `lib/api.ts`

## 3. AI企業リサーチの参照元URL浄化（`1d52b3d`）

### 背景 / 原因
- シード/ダミー案件が `source_url`/`maker_url` に `https://xxxx.example.com` や `https://www.kickstarter.com/projects/example/...` を保持。`company_research_service` がこれを **無検証で保存**し、既存DB行がそのまま「参照元URL」に表示されていた。

### 対応内容
- 共通 `url_validation.py` を新設：`is_valid_business_url()` / `business_url_reason()` / `filter_business_urls()` / `first_valid_url()` / `verify_url_ok()`。ブラックリスト（example.*/dummy/sample/test/localhost/127.0.0.1/githubusercontent、KSの `/projects/example/` slug、http/https 以外）。
- `company_research_service` の保存時に公式サイトを優先順（project→連絡先探索→research結果）で解決、`project_url` は実 campaign_url、`sources` はダミー除外＋200OKのみ。
- **schema境界でもサニタイズ**し、既存DBの example URL も表示させない（DB非破壊で表示のみ無効化）。
- frontend に `isValidBusinessUrl()` / `filterBusinessUrls()` を実装。公式サイト未確認時は「公式サイト未確認」表示。

### 変更ファイル
- backend: `services/url_validation.py`（新規）, `tests/test_url_validation.py`（新規）, `services/company_research_service.py`, `schemas/company_research.py`
- frontend: `components/CompanyResearchPanel.tsx`, `lib/api.ts`
